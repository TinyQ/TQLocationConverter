不同开源实现并非完全同一模型。例如所查 eviltransform Swift 版本使用 `6378137`，BD 正弦项也使用 `π`，而本项目及上述 coordtransform 使用 `π × 3000 / 180`。这些差异意味着不能仅因函数名字相同就相互替代，或把某一个开源库当作官方精度基准。本次没有引入这些库作为运行时依赖，也没有复制其实现；新增代码基于本项目原有公式，参考数据保留了来源与版本。

## 为什么替换旧求逆

旧方法将正向变换后的点构成轴对齐矩形来选择搜索象限。经纬度扰动存在耦合，变换后的区域并不保证仍为这样的矩形；一旦选错区域，继续缩小搜索范围无法修复。旧方法到达次数上限后会直接返回中点，没有单独报告未收敛。

已用原始 Objective‑C 转换函数复现：

```text
WGS‑84 输入（纬度，经度）：35.25, 114.25
原版正向 GCJ‑02：35.249540255704204, 114.255859407090739
原版反向 WGS‑84：35.251493380238543, 114.250000031625078
往返偏差：约 166.06 米
```

为在 macOS 核对原代码，只移除了未使用的 UIKit/多边形部分并重命名冲突的 `pi` 符号；转换数学和搜索逻辑保持原样。新增回归测试明确覆盖该坐标。扩大非网格采样后，还观察到约 270.95 米的旧算法最大往返误差，详见下表。

## 当前方法

将正向转换写作 `f(x) = x + d(x)`，用目标坐标 `y` 求 `f(x) = y`：

```text
r = f(x) - y
若 max(|r.latitude|, |r.longitude|) ≤ 1e-9 度，返回 x
否则 x = x - r，继续检查
```

这是固定点/残差修正迭代。在预期区域内，偏移量相对坐标变化较慢，通常只需少量迭代。每次检查只计算一次正向公式；最多检查 24 次，超限报告 `nonConvergent`。每一步都校验有效性。BD‑09LL 的逆变换先用原有近似逆公式估计，再用同样的方法修正。

牛顿法还可通过 Jacobian 求解，但会增加导数计算、奇异性处理与维护成本；原公式在经度 105° 的 `sqrt(abs(x))` 项还有不可微点。当前残差迭代已通过该位置附近及大范围采样验证，暂不引入这部分复杂度。它也并非对整个地球的任意输入都保证收敛，所以保留明确失败路径。

## 可复现基准

运行：

```sh
swift run -c release ConversionBenchmark
```

基准源码位于 [Benchmarks/main.swift](../Benchmarks/main.swift)。三种求逆共用本项目的同一个正向模型，以隔离求解器差异；旧搜索逻辑按原项目移植，单次近似为 `2y - f(y)`。这不是对外部库完整性能的比较。

样本包括 0.5° 间隔网格中落在多边形内的 4,088 点，以及种子 `0x5451434F` 生成的 10,000 个候选点中落在多边形内的 4,459 点，共 **8,547 点**。增加非网格样本是为了覆盖不同的三角函数相位。测试先正向转换，再求逆；以 Haversine 距离和平均地球半径 6,371,008.8 米度量差异。时间为预热后五次运行的中位数，范围判断及样本生成不计入耗时。

2026-09-28，本机 Apple arm64、macOS 27.0、Swift 6.4、Release 构建的一次记录：

| 求逆方法 | 最大往返误差 | 最大正向残差 | 8,547 点耗时中位数 | 往返超过 1 米的点数 |
| --- | ---: | ---: | ---: | ---: |
| 单次近似 | 4.022000 米 | 4.044891 米 | 1.303 ms | 1,670 |
| 旧四象限搜索 | 270.949795 米 | 270.522473 米 | 27.683 ms | 36 |
| 新残差迭代 | 0.000139 米 | 0.000139 米 | 2.054 ms | 0 |

新方法在这次运行中约为旧方法的 13.5 倍速度。耗时依赖机器、工具链、构建配置及负载，不能保证在所有设备上保持该倍数。固定网格和伪随机样本也不是所有可能输入的证明。

## 精度与适用范围的限制

- 表格描述**同一社区模型内部的数值往返误差**，并非真实坐标、卫星定位误差或地图厂商基准。`1e-9` 度只是停止条件；本库不承诺实际地图达到亚毫米精度。
- 正向公式及常数沿用旧项目；要提高相对真实地图的准确度，需要有来源清晰的厂商/实测控制点，不能仅缩小求逆阈值。
- 多边形为 58 个不同顶点的粗略轮廓，保留是为了延续原项目的地域启发式。它不是官方行政边界、法律判断或厂商覆盖承诺。
- 自动“区域外原样返回”使边界附近的映射存在不连续和歧义。边界附近应由调用方明确 `.unrestricted`，更精细的边界数据也不能完全消除该问题。
- 默认策略对所有方向均只检查输入一次。不要依据不同地区的概括性说法推断 SDK 实际返回的坐标系；以具体 SDK 配置和文档为准。

目前验证包括独立正向样本、六向往返网格、固定种子非网格样本、经度 105° 邻域、边界点、旧错误回归、非法输入、并发调用和两种语言一致性；没有使用官方服务密钥，也没有真实测绘控制点验证。
